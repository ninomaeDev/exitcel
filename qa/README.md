# Exitcel QA — テスト一式

Exitcel v1.0 に対して実施した評価検証（テストケース292件）の実行環境一式です。
**外部ライブラリ不要**。Node.js とブラウザだけで、誰でも同じ手順で再実行できます。

- 公開している実施記録: <https://creators-hub-demo.polar-demo-lab.workers.dev/qa-portfolio>
- テストケース一覧・不具合一覧（xlsx / CSV）は上記ページからダウンロードできます

---

## テストの構成

| 層 | ケース数 | 何を確かめるか | 実行時間 |
|---|---|---|---|
| ロジック層 | 242件 | 数式・関数・参照・表示形式・ファイル入出力・性能 | 約1.9秒 |
| UI実機層 | 50件 | キーボード操作・リボンのボタン・クリップボード・xlsx往復 | 約1.0秒 |
| **合計** | **292件** | | **約2.9秒** |

判定基準（テストオラクル）は「**Microsoft Excel と同じ結果になるか**」。
期待結果はすべて「Excel ならこうなる」で記述しています。

---

## 1. ロジック層を実行する

```bash
cd qa
node run.js
```

出力例:

```
総ケース数: 242 / PASS: 241 / FAIL: 1
---- FAIL 一覧 ----
TC-H-034 | 関数(日付) | 日付シリアルの起点(1900/1/1=1)
   手順: =DATE(1900,1,1)
   期待: 1   実際: 2
---- CI 判定 ----
既知の失敗として許容: 1 件 (TC-H-034)
回帰なし
```

結果は `results.json` に保存されます。

終了コードは CI 用です。`known-failures.json` に登録した既知の失敗ではビルドを落とさず、
**それ以外が失敗したとき（＝回帰したとき）だけ 1 を返します**。あわせて、
既知として登録したまま直っているケースがあるときも 1 を返します
（ベースラインが実態より甘いまま放置されるのを防ぐため）。

Node.js はブラウザではないため、`document` や `Blob` が存在しません。
`harness.js` がそれらを最小限だけ用意した上で、Exitcel の
`util.js` / `formula.js` / `model.js` / `xlsxio.js` / `objects.js` を読み込みます。
**アプリのコードには一切手を入れていません**（テストのために本体を書き換えると、
テストしている対象が本物でなくなるため）。

## 2. UI実機層を実行する

```bash
node ../server.js 8777
```

1. ブラウザで <http://localhost:8777/> を開く
2. 開発者ツール（F12）→ コンソール を開く
3. `qa/ui-suite.js` の中身を貼り付けて Enter
4. `await runUiSuite()` と入力して Enter

コンソールに結果が出ます。結果をファイルに保存したい場合は、別ターミナルで

```bash
node collector.js
```

を起動してから `await runUiSuite({post:true})` を実行すると `ui-results.json` に保存されます。

UI実機層は、`Grid.setSel()` などアプリの公開APIでセルを選び、
**本物の KeyboardEvent / click / ClipboardEvent を発火**させて動かします。
「Ctrl+Z を押す」「リボンの結合ボタンを押す」「Excel からコピーした TSV を貼り付ける」を
利用者と同じ経路で再現するためです。

## 3. 成果物（xlsx / CSV）を作り直す

```bash
node gen-xlsx.js [出力先ディレクトリ]
```

`results.json` + `ui-results.json` + `defects.js` から
「サマリ / テストケース一覧 / 不具合一覧」の3シート構成の xlsx と CSV を生成します。

書き出しには **テスト対象である Exitcel 自身の xlsx エクスポータ**を使っています
（自作機能を自作の成果物作成に使う＝ドッグフーディング）。
生成したファイルを読み込み直して内容が保たれることも確認済みです（TC-U-034〜038）。

## 4. 公開ページを作り直す

```bash
node build-page.js [出力先のHTMLパス]
```

`results.json` / `ui-results.json` / `defects.js` から公開ページの HTML を生成します。
**ページ上の数値はすべて実行結果から自動生成**しており、手で書き写していません
（転記ミスで実績の数字がずれるのを防ぐため）。

## ファイル構成

```
qa/
├─ harness.js       ブラウザ用モジュールを Node.js に読み込ませる土台
├─ lib.js           セル入力→再計算→表示値取得 のヘルパ
├─ cases-a.js       テストケース A(数式エンジン20件) / B(組み込み関数88件)
├─ cases-b.js       テストケース C〜G(参照・行列操作・表示形式・入出力・性能 84件)
├─ cases-c.js       テストケース H(関数の境界値・異常系 50件)
├─ run.js           ロジック層の実行と結果集計
├─ ui-suite.js      UI実機層 50件（ブラウザのコンソールで実行）
├─ collector.js     ブラウザの実行結果を受け取って保存する小さなサーバー
├─ defects.js          不具合報告票 10件（再現手順・原因調査・修正方針・対応状況つき）
├─ known-failures.json CI で許容する既知の失敗（理由と判断日つき）
├─ gen-xlsx.js         テストケース一覧・不具合一覧の xlsx / CSV を生成
├─ build-page.js       公開ページ(HTML)を実行結果から生成
├─ results.json        ロジック層の最新実行結果
└─ ui-results.json     UI実機層の最新実行結果
```

## テストケースの書き方

1件は次の形式です。実行者によって判定がブレないよう、
期待結果は「画面に表示される値そのもの」で書いています。

```js
{
  id:   'TC-B-079',
  cat:  '関数(日付)',            // 大分類
  view: 'EDATE 翌月同日(月末補正)', // テスト観点
  tech: '境界値',                 // 使ったテスト技法
  pre:  '-',                      // 前提条件
  step: '=DAY(EDATE(DATE(2026,1,31),1))', // 手順
  exp:  '28',                     // 期待結果（Excelの挙動が根拠）
  run:  () => calc({}, '=DAY(EDATE(DATE(2026,1,31),1))'),
}
```

## 実施の経過

### 第1回：テスト実施（2026年8月23日）

- 292件を全件実行 / 274件合格・18件不合格（合格率93.8%）
- 不具合 **9件** を起票（重要度「中」3件 / 「軽微」6件）
- 不合格のうち4件は **テストケース側の誤り** と判明したため、ケースを是正して再実行

検出した不具合のうち重い3件（いずれもエラー表示にならず静かに誤るもの）:

| ID | 概要 |
|---|---|
| BUG-001 | `EDATE(2026/1/31,1)` が 2/28 ではなく **3/3** を返す（月末補正なし） |
| BUG-002 | `POWER(-8,1/3)` が `#NUM!` ではなく **NaN** を返し、SUM経由で合計まで汚染される |
| BUG-003 | 同名シートを含むファイルを読み込むと、シート間参照が**別シート**を指す |

### 第2回：修正と再テスト（2026年8月25日）

起票した9件をすべて修正し、全件を再実行しました。

- **292件中 291件合格**（ロジック層 241/242・UI実機層 50/50）
- 起票済み **9件すべてを修正済み**、担当したテストケースが PASS に転じたことを確認
- 修正は不具合票の「修正方針」に沿って行い、**該当箇所に BUG-番号のコメントを残しています**（後から追跡できるようにするため）

再テストの過程で、さらに2件の発見がありました。

**1. テストケース側の期待値誤り（TC-U-042）**

「計算不能な結果が後続の集計を汚染しない」の期待値を `10`（エラーを飛ばして集計する）としていましたが、**Excel は SUM の範囲にエラー値があればそのエラーを返します**。期待値そのものが誤りだったため、`#NUM!` に是正しました。BUG-002 を直したことで、この観点は本来の意図どおり満たされています。

**2. 未起票の失敗を発見し、判断のうえ保留（BUG-010 / TC-H-034）**

`DATE(1900,1,1)` が Excel の `1` に対して `2` を返す件を調査しました。

| 日付 | 実装 | Excel |
|---|---|---|
| 1900/1/1 | 2 | 1 |
| 1900/2/28 | 60 | 59 |
| **1900/3/1** | **61** | **61** |
| **1999/12/31** | **36525** | **36525** |

**1900年3月1日以降は完全に一致**し、それ以前だけ1ずれます。原因は Excel 側の既知の不具合で、Excel は実在しない「1900年2月29日」をシリアル値60として数えています。**実装のほうが数学的に正しい**ため、正しいカレンダーを壊してまで合わせる判断はせず、`known-failures.json` に理由を添えて登録し、CI の回帰検知対象から外しています。

テストを緑にすること自体は目的ではないので、**判断の記録を残して落としたまま**にしています。
